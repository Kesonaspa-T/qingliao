用 `--remote-debugging-port` 把**真在跑的 `dist/qingliao-win.exe`** 挂上 CDP，登录走的是真界面（填名字密码 → 点「注册新账号」）。

**第 11 条为什么没过（不是代码问题）**：`downloadWillBegin` 正常触发、`suggestedFilename` 也对，
说明壳**没有**拦 `will-download`；但 Chromium 停在 `state=canceled / receivedBytes=0`。
这台机器的会话沙箱不让 Chromium 往工作区外写盘——同一环境里它连 `%APPDATA%` 的 singleton 锁都建不了
（`Lock file can not be created: 拒绝访问`），本次是加了 `--no-sandbox` + `--user-data-dir` 到工作区才跑起来的。
真实桌面上双击 exe → 点开她的照片 → 「保存图片」→ 看「下载」文件夹即可确认。

## 7. 本机测试环境的两个坑（只影响测试，和 exe 无关）

1. DSH 自己跑在 Electron 上，环境里有 `ELECTRON_RUN_AS_NODE=1`。不清掉的话，
   任何 Electron 程序（包括我们的 exe）都会被当成 node 解释器，参数全报 `bad option`。
2. 会话沙箱下 Chromium 的自带沙箱起不来（`FATAL:mojo platform_channel` / `拒绝访问`），
   所以测试时给 exe 加了 `--no-sandbox`，并把 `--user-data-dir` 指到工作区。
   **源码和打包配置都没有为此改动。**
